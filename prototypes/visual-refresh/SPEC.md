# CEPM 界面视觉改造规格

2026-10-30。依据已完成的 Q1–Q8 访谈、用户调用 to-spec 的发布指令，以及样稿的三轮浏览器批注修订。功能已验收；本规格覆盖视觉改造。可先推进 HTML 样稿，样稿获用户确认后才能改造生产界面。

## Problem Statement

用户已能完成扩展安装、检查更新、浏览器加载与确认，但界面仍有大量字符图标、缺少层级的按钮和拥挤的说明。用户难以快速辨认当前浏览器配置、扩展状态与下一步操作。之前批准的 A 原型建立了操作结构，但实际应用没有达到期望的视觉质量，原型自身的字符图标也不适合作为成品标准。

## Solution

保留 A 原型的操作结构和试用后已经简化的流程，整体采用 OpenLogi 的浅色视觉语言：浅灰工作区、白色内容面板、蓝色主操作、统一字体与留白、克制的边框及浮层阴影。

扩展显示自身图标，浏览器显示正式品牌图标，操作使用 Lucide SVG。扩展列表只保留辨认和行动所需的信息，其余内容放进详情。复用旧 HTML 原型制作新版视觉样稿并由用户确认，再落实到全部原生界面。验收只使用正常窗口，不建立多尺寸测试矩阵。

## User Stories

1. 作为扩展用户，我希望打开应用就能看清当前浏览器和 Profile，以便避免维护错误的目标。
2. 作为多配置用户，我希望从左侧顶部快速切换 Profile，以便继续管理另一配置的扩展。
3. 作为多配置用户，我希望置顶多个常用配置，以便减少查找时间。
4. 作为多配置用户，我希望置顶操作不改变当前选择，以便整理列表时不中断当前任务。
5. 作为扩展用户，我希望重开应用恢复最后选择，以便继续此前工作。
6. 作为扩展用户，我希望目标缺失时看到定位入口，以便修复目标而不是误用默认配置。
7. 作为扩展用户，我希望通过真实图标和名称辨认扩展，以便快速找到所需项目。
8. 作为扩展用户，我希望图标缺失时仍看到整齐的统一占位图标，以便图标问题不影响使用。
9. 作为扩展用户，我希望列表显示名称、版本、必要状态及安装和最后更新时间，以便快速了解维护情况。
10. 作为扩展用户，我希望点击扩展行进入右侧完整详情页并保留左侧导航，以便有充足空间查看信息。
11. 作为扩展用户，我希望需要处理的扩展显示明确的下一步，以便知道该加载、重载还是解决异常。
12. 作为扩展用户，我希望“添加扩展”是清楚的页面主操作，以便首次使用时知道从哪里开始。
13. 作为扩展用户，我希望检查更新与原生管理页入口容易找到但不过度突出，以便页面保持安静。
14. 作为扩展用户，我希望空列表提供直接的添加入口，以便不必阅读大量介绍。
15. 作为扩展用户，我希望本地目录、Release 和仓库目录沿用两步添加流程，以便选择来源并预览产物后即可安装。
16. 作为扩展用户，我希望默认版本简单明确、其他版本按需展开，以便兼顾简单安装与任意有效版本选择。
17. 作为扩展用户，我希望存在多个附件或扩展目录时清楚选择，以便避免安装错误产物。
18. 作为扩展用户，我希望后续更新只需一次结果提醒，以便不用每次重复三步引导；首次安装保留必要的加载说明与 ID 记录。
19. 作为扩展用户，我希望打开原生管理页失败时仍有手动打开入口，以便完成安装。
20. 作为扩展用户，我希望后续更新复用已记录的扩展 ID，以便避免重复输入。
21. 作为扩展用户，我希望核对指定版本后才确认完成，以便不会把文件部署误认为浏览器已生效。
22. 作为扩展用户，我希望未完成的加载可以稍后继续，以便不用一次完成全部操作。
23. 作为扩展用户，我希望详情默认展示来源、路径、ID、版本、时间和历史，以便直接追溯安装，不必展开折叠区。
24. 作为扩展用户，我希望降级、重新部署、冲突和恢复仍有清晰提示，以便理解操作后果。
25. 作为扩展用户，我希望检查中、无新版本和失败有清楚且克制的反馈，以便知道当前结果。
26. 作为批量更新用户，我希望分别看到各扩展结果，以便处理失败项而不误解其他成功项。
27. 作为扩展用户，我希望各页面的按钮、输入框、菜单和图标风格一致，以便不必重新学习操作。
28. 作为键盘用户，我希望主要操作有可见焦点和合理焦点返回，以便可靠操作菜单与对话框。
29. 作为扩展用户，我希望纯图标按钮有提示和可读名称，以便理解按钮用途。
30. 作为扩展用户，我希望长名称和路径不破坏正常窗口布局且能查看完整内容，以便辨认目标。
31. 作为扩展用户，我希望安装后的应用也能正确显示全部图标，以便获得与演示一致的体验。
32. 作为产品验收者，我希望先确认新版 HTML 样稿，再对照真实应用，以便及时发现视觉偏差。
33. 作为扩展用户，我希望检查后在列表看到新版本及目标版本号，以便直接决定是否更新。
34. 作为扩展用户，我希望扩展操作集中在详情顶部，以便在同一位置找到更新、版本选择、打开目录和恢复；浏览器扩展管理保留左侧入口，更新提醒内可提供轻量跳转链接。

35. 作为多配置用户，我希望在不按浏览器分组的菜单中看到每个 Profile 的受管扩展数量，以便快速选择目标。
36. 作为扩展用户，我希望看到应用全称、Logo 和关于页，以便识别应用并查看版本及项目入口。

37. 作为扩展用户，我希望在更新提醒内直接跳转浏览器管理，以便就近完成重载，仍只提交一次结果确认。
38. 作为扩展用户，我希望详情描述来自扩展清单，以便不会把管理器编写的介绍误认成作者说明。
39. 作为扩展用户，我希望在详情中对照同一扩展在各浏览器/Profile 的文件版本、已确认版本和状态，并能切换到具体安装记录，以便定位版本差异。

## Implementation Decisions

- 延续 Rust 核心与 GPUI/gpui-kit 界面分离的架构，使用现有组件生态，不照搬 OpenLogi 的 fork 补丁，不更换 GUI 框架。修改范围主要是桌面展示、主题、资源和薄视图适配；无需改变安装记录的持久化结构或核心安装用例契约。
- A 原型是操作结构依据：左侧顶部紧凑 Profile 切换、多置顶、恢复上次选择，右侧扩展库，详情与引导按需展开。旧绿色配色、字符图标和旧三步添加不再约束本轮。保留两步添加、首次加载说明及 ID 记录、后续复用 ID 和明确核对后确认。后续更新使用一次结果提醒，取代三步引导。
- 本轮只交付浅色主题。应用级主题统一自绘区域与组件样式，避免页面颜色和默认组件主题不一致；只建立本应用需要的薄样式层。
- 以下采用 OpenLogi 固定研究提交的源码取值作为样稿基线，样稿确认时可调整并记录，生产实现须与获批样稿一致：

| 项目 | 样稿基线 |
| --- | --- |
| 背景与面板 | 页面 `#f4f4f6`，面板白色，边框 `#d9d9e0`。 |
| 文字 | 正文 `#1a1a1d`，次级 `#6b6b73`；普通文字对比度至少 4.5:1。 |
| 主按钮 | 蓝底白字；普通 `#2563eb`、悬停 `#1d4ed8`、按下 `#1e40af`。 |
| 普通按钮 | 白底，悬停 `#e9e9ee`、按下 `#e1e1e8`；焦点和选中强调 `#3b82f6`。 |
| 控件 | 独立按钮、输入框、选择控件高 30px；轻量及图标按钮按组件规范适配。 |
| 字体 | 大标题 26px，区块标题 20px，条目标题与正文 15px，说明 12px，按标准 rem 基准。 |
| 间距 | 主内容内边距 20px，卡片内边距 16px，标题到内容间隔 12px。 |
| 层次 | 白面板、单层细边框；卡片圆角为控件圆角的 1.5 倍；阴影主要用于浮层，避免卡片层层嵌套。 |

- 操作图标使用 Lucide SVG，Chrome/Edge 使用随应用分发的品牌图标；不用字符、字母、emoji 或 CSS 仿制标识替代图标。正常文本标点不受限制。
- 详情描述仅来自当前安装产物的 `manifest.json` 描述字段；不按名称自行编写文案、不从 README 或网络生成介绍。缺失、无效或无法解析的本地化占位符不显示描述。样稿已删除此前人工编写的 OpenCLI 介绍；HTML 不假装读取真实清单。
- 扩展图标优先读取固定安装目录内清单声明的有效本地资源，不额外从网络获取。缺失、不可读、解码失败或路径越界时使用拼图 SVG；图标失败不阻塞列表或安装。此变化属于展示资源读取，不扩大对其他本地文件的访问范围。
- 列表行常显图标、名称、版本和必要状态，次级信息行显示安装与最后更新时间；检查发现新版本后，显示目标版本徽标和更新入口，无新版本或失败显示对应结果。整行可进入详情，移除重复“详情”按钮。待加载、待重载或异常项显示对应的下一步；这些按钮与整行点击独立，不同时触发。
- 详情占满左侧导航右侧的主内容区，不使用居中详情弹窗；提供返回列表入口，切换 Profile 关闭当前详情。版本与确认状态、安装/更新/检查时间、来源、固定目录、扩展 ID 和最近历史默认展开。全部扩展操作集中在详情顶部，按当前状态突出下一步，更新、任意版本选择、打开目录和恢复均在同一操作区；版本选择和恢复确认可继续使用任务对话框。页面主按钮是“添加扩展”，“检查更新”和“打开浏览器扩展管理页”使用较轻样式。普通升级、批量升级和任意版本选择等既有入口仍可到达。
- 时间优先读取既有安装记录和历史（已有 `installed_at` / `updated_at`），不为展示改写核心记录契约。安装时间为首次文件部署时间；最后更新时间反映后续成功部署或恢复，检查更新及浏览器确认不能改变它们。未发生后续更新显示“尚未更新”，旧记录无法确定的值显示“未记录”，不得用当前时间补造；最近检查独立显示。列表展示简短日期，详情展示完整本地时间。
- Profile 菜单以浮层展开，不推动侧栏及列表；采用扁平列表，不再显示 Chrome/Edge 分组标题；每行保留品牌图标和“浏览器 · Profile”，显示该配置由本应用管理的安装记录数量（含待核对项，不扫描或冒称浏览器内全部扩展）。支持多个置顶，置顶项排在前面，置顶不切换当前配置。除详情中的各配置安装对照外，列表、计数、待办、更新、记录和新安装仍限定当前 Profile；目标缺失不静默切换。
- 删除“自动记住上次选择的配置”等机制说明，以及侧栏底部重复的浏览器/Profile 文本；恢复上次选择的行为继续保留。
- 应用标题显示全称 Chromium Extension Package Manager，并使用统一应用 Logo；侧栏提供“关于”，展示全称、Logo、实际应用版本、简短用途、项目主页与问题反馈链接。样稿版本标为视觉样稿，不冒称已发布的新版本。
- 详情新增“各配置安装情况”对照，展示同一扩展的受管安装：浏览器/Profile、文件版本、已确认版本、状态，标记当前记录。待核对时把既有确认标为“上次”，首次未确认显示“尚未确认”。点击配置名称切换顶部管理目标并进入对应详情；之后所有动作只作用于选中的安装。此处是只读对照与导航，不加入跨配置更新/安装或扫描未纳管扩展。
- 对照中的“同一扩展”必须由来源与产物证据确认，不能只按名称、图标或因解压目录不同而变化的浏览器扩展 ID 合并。实现优先使用已有来源信息派生：同一仓库目录、同一本地来源目录或能够可靠对应的 Release 产物；不靠猜测去掉附件文件名中的版本号，也不自动合并不同来源类型。证据不足的安装各自展示，不建立新注册中心或自动识别服务。HTML 用明确标记的三份 OpenCLI 示例演示，不能作为生产归并算法。
- 首次待加载不能显示安装成功；文件部署不等于生效。详情保留磁盘安装版本、生效版本和确认方式。打开浏览器和切换步骤不提交用户确认，只有核对指定版本后的明确操作才提交。
- 后续更新、降级、重新部署或恢复文件后，以简短结果提醒代替“打开浏览器 → 重载 → 确认”的三步流程。提醒包含扩展、目标 Profile 和需核对的版本，只有“确认更新完成”和“更新失败”两个结果按钮；关闭不提交结果，仍可从待处理继续。确认完成后记录用户确认；失败保留当前文件及历史确认，显示用户反馈失败与重试/显式恢复入口，不能自动回滚或误标已生效。提醒展示期间左侧原生管理入口仍可使用；切换页面/配置可关闭提醒但不能确认成功。首次安装保留加载说明及首次 ID 校验。
- “浏览器扩展管理”在左侧导航保留固定入口；更新结果提醒正文允许一个轻量跳转链接，使用同一目标 Profile 的打开行为。详情操作栏不重复放按钮，首次加载说明继续指向左侧入口；左侧入口直接发起打开请求，失败时展示手动地址等兜底，不增加成功前的二次打开弹窗。原生扩展页继续承接浏览器加载、重载、启停、权限和移除；打开失败保留地址复制及手动继续入口。更新、降级、同版本重新部署、冲突、失败恢复的安全边界不变。
- 弹窗的关闭、返回、取消及稍后继续按实际流程呈现，移除重复的通用底栏说明；不改变操作提交边界。按钮提供正常、悬停、按下、禁用、加载和键盘焦点状态。纯图标按钮有提示及可读名称；状态不能只靠颜色表达，不伪造百分比进度。
- 正常窗口基准为 1120×780，核心操作不遮挡，无页面横向滚动，长内容可纵向滚动。名称和路径可省略，但可查看完整内容。不增加小窗口、多尺寸或响应式适配测试，也不据此禁止用户调整窗口大小。
- 全部现有页面采用同一视觉规范，覆盖范围如下。此表描述现有行为的呈现，不授权新增安装能力。

| 界面 | 覆盖状态 |
| --- | --- |
| 应用框架 / Profile / 关于 | 全称与 Logo、关于页与版本、扁平菜单、受管数量、多置顶、当前选择、长名称、未绑定、目标缺失、手动定位。 |
| 扩展库 / 待处理 | 正常、空列表、等待首次加载、等待重载或核对、恢复需要处理、检查中、有新版本、无新版本、失败。 |
| 添加扩展 | 三种已有来源、两步添加、其他版本、多个附件或根目录候选、获取失败。 |
| 加载与核对 | 侧栏入口、更新提醒正文链接及手动兜底、首次加载与 ID、后续单次结果提醒、确认完成、更新失败、关闭后继续。 |
| 详情 / 更新 / 恢复 | 来源和历史、普通升级、显式降级、同版本重新部署、冲突、恢复确认、失败及重试。 |
| 批量结果 / 操作记录 | 各项成功、待核对、失败或跳过，各自原因及可用下一步。 |

- 实施按两个阶段推进：先复用旧 HTML 原型制作扩展库、Profile 菜单、两步添加和加载引导，包含正常、空列表、待处理和错误示例；用户确认样稿后，再改造全部 GPUI 页面、验证并更新本机应用。HTML 仅为设计依据，不能替代原生应用验收。

## Testing Decisions

- 主要验收入口是用户能操作的实际桌面应用：在正常窗口内与获批 HTML 样稿进行截图和操作对照。沿用现有原生 GUI 冒烟方式；浏览器中的 HTML 测试只能验证样稿，不能证明 GPUI 实现通过。
- 保留此前已确认的 Rust 安装用例测试入口，检查对外返回状态、真实临时目录文件和重开后的安装记录。只有当展示改造涉及这些行为时才补充相应测试，不按按钮数量重复核心测试。
- 好的测试验证可见行为和边界：点击行进入详情，行内按钮执行其自身动作；菜单不挤动页面；置顶不切换目标；打开管理页不提交确认；明确核对后才提交；图标故障回退而不影响操作。不要断言私有辅助函数、精确内部调用顺序或用测试复制实现。
- 验证后续更新不再出现步骤条；侧栏入口和提醒内链接均可操作且指向当前 Profile；确认完成、失败、关闭分别产生正确结果。失败和关闭均不覆盖历史生效确认、不自动恢复；首次 ID 校验保留。检查 Profile 数量跟随对应安装记录，置顶不改变选择；标题、Logo 与关于页显示一致。
- 验证跨配置对照中的不同文件/确认版本、待核对与首次未确认状态；点击其他配置后目标、详情和操作作用域一起切换，确认一个配置不修改其他记录。同名不同产物不误合并，描述缺失不编造内容。
- 验证列表的新版本标记与目标版本一致；查看详情不打开遮罩，来源和时间默认可见，操作位于统一区域；更新或恢复文件后刷新最后更新时间，安装时间保持不变，单纯检查及确认不改变两项时间。
- 视觉检查覆盖正常、有新版本、空列表、待加载、待重载、失败、恢复及批量混合结果；检查信息层次、按钮层级、对齐、字体、长文本和滚动。仅测试 1120×780 正常窗口，不增加其他尺寸或平台专项矩阵。
- 检查主题、资源加载和主要导航：图标在开发与打包应用中都可见；本地图标有效时显示自身图标，缺失、损坏或越界时使用统一回退；不发起额外图标下载。仅在资源处理确有新增行为时，为其外部行为增加少量验证。
- 验证主要按钮的状态、键盘可达性、可见焦点、纯图标提示与可读名称；关闭菜单或对话框后焦点回到合理位置。恢复、取消及稍后继续不改变既有业务语义。
- 先例包括现有 Profile 用户旅程、MVP、主 Profile 本机安装验收及 Rust 安装/更新/恢复测试。继续执行改动所需的格式、静态检查、构建及相关测试，不引入新测试框架或全量像素快照平台。
- 使用测试配置与受控场景验证界面，不为纯视觉变更重复安装扩展或重启用户浏览器。实际发生业务行为变化时，针对受影响路径回归；未验证的平台不声明已通过。
- 完成条件包括用户批准的 HTML 样稿、全部现有页面使用统一样式、打包应用截图与操作验收通过、本机应用更新，以及必要检查结果记录。样稿通过或构建成功均不能单独算本规格完成。

## Out of Scope

后台自动检查或自动更新、自动操作浏览器、新来源能力、源码构建、已有扩展接管、辅助扩展、跨配置批量安装或迁移、凭据管理、核心安装行为重写、深色或自定义主题、复杂动效、通用设计系统、全新测试平台、小窗口及多尺寸专项验收、额外 Windows/Edge 专项验证、签名公证流程。

不因旧原型中出现搜索、筛选、更多字段或 A/B/C 演示切换器就将其加入产品；不复制 OpenLogi 的硬件导航、品牌标志及专属依赖。
