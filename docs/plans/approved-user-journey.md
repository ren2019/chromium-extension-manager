# 已批准的 A 用户旅程

2026-10-29，用户明确回复“原型批准”。这是 MVP 规格的实现约束，不再把初始单页功能表单视为最终 GUI。

原型主来源：[独立原型分支](https://github.com/ren2019/chromium-extension-manager/tree/prototype/user-journey/prototypes/user-journey)，批准时交互代码为 `f869163`，批准记录为 `6aa176c`。HTML 不并入生产，Rust + GPUI 重写实现。

## 布局与操作范围

- A 扩展库布局：左侧菜单、右侧扩展列表；详情和分步向导按需打开。
- 左侧菜单顶部为紧凑的浏览器 / Profile 快速切换器，展开后按浏览器分组。只有选定具体配置才能管理其扩展。
- 配置列表允许多个置顶，置顶集中显示并带浏览器名；取消置顶不改当前选择或安装。
- 保存最后选中的配置，重开恢复同一目标；找不到时保留目标和数据并提示定位，不能静默改用默认配置。
- 列表、计数、待办、检查更新、批量更新、记录均限于当前配置。一次添加继承当前目标，不提供跨配置批量安装或迁移。
- 同一个扩展在不同 Profile 是独立安装：固定目录、版本、备份、ID 和确认状态独立。

## 目标身份

显示名称只是标签。目标绑定具体浏览器应用、用户数据目录及其中的 Profile 目录，使用稳定内部标识关联安装。只读取配置名称和位置等必要元数据，不读取浏览历史、Cookies、登录信息或接管已有扩展。

常见位置能发现时提供候选；无法发现时允许手动提供浏览器应用与 Profile Path，并在浏览器 version 页核对。路径不存在则暂停该目标维护。旧版只有自由文本标签的记录应明确要求定位，不能猜测到某个真实 Profile 或沿用不可靠确认。

## 用户旅程

1. 选择浏览器配置 → 添加来源 → 预览产物/版本 → 确认安装目标 → 文件准备 → 浏览器首次加载引导 → 用户核对。
2. 检查更新 → 预览目标版本 → 备份与部署 → 待重载/核对 → 用户确认。可稍后继续，旧确认明确为历史。
3. 降级与同版本重新部署均明确确认；冲突暂停；明确加载失败后恢复旧文件并再次核对。
4. 批量更新只处理当前配置的普通升级；每项独立结果，失败不撤销其他成功项。

## 与浏览器原生管理页交接

侧栏、详情、加载/重载指引提供“打开浏览器扩展管理页”。使用绑定的应用和 Profile 请求打开 chrome://extensions 或 edge://extensions，不将裸 URL 交给默认浏览器。浏览器原生页保留加载、重载、启停、权限和移除操作；回 CEPM 后核对。

启动成功不等于目标正确或扩展已生效，失败时保留复制管理页地址的兜底。只验证 macOS Chrome 的真实路由，不增加 Windows/Edge 验证门槛。自动读状态、代点、嵌入内部页面均不属于本次批准；不引入辅助扩展或修改浏览器安全设置。

## 验证与票据落点

沿用已批准的 Rust 用例入口与真实文件系统测试，GUI 少量 macOS 冒烟。#3 补齐 Profile 绑定、偏好和 A 界面基础；#4 承接安全更新/恢复；#5/#6 把远程来源接入同一向导；#7 收口当前配置批量更新、原生页路由和 OpenCLI 验收。保留原五票拆分，不另造平台或插件架构。

## 试用后的简化（2026-10-29）

用户实际操作 OpenCLI 检查更新与加载后反馈字、按钮和交付步骤过多。界面按“选择配置 → 安装 → 以后更新”收敛：

- 列表只显示名称、简短状态和下一步；来源、路径、历史确认及版本切换收进详情的更多选项。
- 加载向导每次只展示一个步骤。首次安装记录 ID；后续复用同一安装已记录的 ID。最后明确询问浏览器是否显示指定版本，点击“是，已完成”才提交用户确认，不再重复输入版本及勾选声明。
- 打开浏览器或进入下一步不提交确认。文件部署、用户确认与恢复的核心约束不变。
- 备用地址和恢复入口放在“遇到问题”；首次 Release 安装默认折叠完整版本列表，保留任意版本选择。
- 没有更新时直接返回列表显示结果；更新完成部署后直接进入加载指引。
- ZIP 只有一个扩展目录时自动选取，多个候选时仍由用户选择。来源与安装预览合为两步，取消重复的位置确认页。

后台自动检查及首页逐项更新状态尚未包含在这一轮简化中。
