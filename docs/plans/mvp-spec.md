# CEPM MVP 实现规格

依据：2026-10-29 PRD v0.4、设计访谈、最小实验及停止 Windows/Edge 补测的推进指令。测试入口和 5 项任务拆分已由用户确认，作为开发基线。

## Problem Statement

用户安装非商店扩展时，需要自己找版本、下载解压、保管目录、替换文件和重载浏览器。附件可能选错，仓库标签不一定等于扩展版本，文件更新也不代表浏览器已生效；私有来源和本地目录让维护更分散。

## Solution

提供 Rust + GPUI 桌面应用，把公开/私有 GitHub Release ZIP、指定引用的仓库扩展子目录和本地目录统一为可安装产物。用户确认来源和版本后，应用负责校验、固定目录部署、更新和失败恢复。首个可交付流程使用普通浏览器的手动加载、重载与版本核对，明确显示磁盘安装版本、生效版本和确认方式。

Windows/macOS 与 Chrome/Edge 保留为产品目标；本轮按用户指令不再做 Windows/Edge 专项验证。基于 macOS Chrome 已有证据推进，未测兼容性不标成已通过。

## User Stories

1. 作为扩展用户，我希望通过一个简单桌面界面添加来源，以便集中维护扩展。
2. 作为本地扩展用户，我希望选择包含完整产物的目录，以便无需远程 CLI 就能安装。
3. 作为扩展用户，我希望安装前看到清单名称和版本，以便确认装的是目标扩展。
4. 作为扩展用户，我希望应用复制文件到固定安装目录，以便来源目录变化不影响已安装扩展。
5. 作为扩展用户，我希望获得首次手动加载指引和可复制路径，以便在日常浏览器配置完成持久安装。
6. 作为扩展用户，我希望记录目标浏览器配置与扩展 ID，以便以后核对同一安装。
7. 作为扩展用户，我希望分别看到磁盘安装版本和生效版本，以便知道是否仍需重载。
8. 作为扩展用户，我希望手动核对的结果标为用户确认，以便知道确认方式。
9. 作为扩展用户，我希望重新打开管理器时安装记录还在，以便持续维护。
10. 作为扩展用户，我希望退出管理器后扩展仍可用，以便不必让管理器常驻。
11. 作为本地扩展用户，我希望检查来源目录的新版本，以便主动更新。
12. 作为本地扩展用户，我希望同版本文件变化单独提示并经明确选择部署，以便避免静默覆盖。
13. 作为扩展用户，我希望显式选择可获取的旧版本，以便需要时降级。
14. 作为扩展用户，我希望固定安装目录有手动改动时暂停更新，以便保留自己的修改。
15. 作为扩展用户，我希望部署前验证和备份，以便失败后仍有可恢复的旧文件。
16. 作为扩展用户，我希望报告明确加载失败后恢复旧文件并重新核对，以便恢复使用。
17. 作为扩展用户，我希望无法读取浏览器状态时保持待验证，以便系统不误判成功或失败。
18. 作为 GitHub 用户，我希望添加仓库或 Release 地址后看到正式版本与附件，以便选择预构建扩展。
19. 作为 GitHub 用户，我希望附件不明确时自己选择，以便应用不猜错安装包。
20. 作为私有仓库用户，我希望应用使用已授权的 gh 获取产物，以便凭据继续由 CLI 管理。
21. 作为扩展用户，我希望 CLI 缺失、权限失败、下载失败时看到原因和下一步，以便修复后重试。
22. 作为仓库目录用户，我希望指定分支、标签或提交和子目录，并记录具体提交，以便追溯安装内容。
23. 作为扩展用户，我希望无效清单、危险归档或摘要不一致被拒绝，以便旧安装不受影响。
24. 作为多个扩展的用户，我希望一键检查并更新，每项独立报告，以便一个失败不影响其他项。
25. 作为 OpenCLI 用户，我希望 Browser Bridge 安装和更新后能通过 doctor 连接检查，以便确认实际可用。
26. 作为扩展用户，我希望错误显示阶段、原因和修复建议，并保存必要日志，以便排查问题。

27. 作为扩展用户，我希望先选择具体浏览器与 Profile，再维护其中的扩展，以免更新或确认错误的配置。
28. 作为扩展用户，我希望置顶多个常用配置并在重开时恢复最后选择，以便快速继续工作。
29. 作为扩展用户，我希望打开当前配置的浏览器原生扩展页，以便完成加载、重载与原生管理后回到 CEPM 核对。

## Approved UI

用户已批准 [A 用户旅程](./approved-user-journey.md)：左侧顶部紧凑浏览器/Profile 切换、多个置顶、恢复上次选择、当前配置的列表/待办/批量更新、分步添加与核对、原生管理页交接。该文档及独立原型分支是 GUI 实现依据。

## Implementation Decisions

- 一个 Rust 核心和一个薄 GPUI 界面；从已验证的上游依赖起步。核心提供添加、检查、部署、确认与恢复等用例入口，界面只驱动操作和显示结果。获取与部署放在后台，界面保持可响应。
- 初版模块围绕来源获取、安装用例和界面划分；安装记录先采用本地结构化文件，使用安全替换保存。无需服务端、常驻进程、插件框架或数据库服务。
- 每个安装使用独立、稳定的内部标识与固定安装目录，和来源目录分离。记录来源定位、解析后具体引用、目标浏览器配置、扩展 ID、磁盘安装版本、历史确认及当前操作状态。
- 只管理由本工具创建的安装。不扫描接管已有扩展，不迁移浏览器账户或配置。浏览器配置绑定实际应用、用户数据目录和 Profile 目录，显示名不作唯一身份；可发现或手动定位，只读必要名称/位置元数据，不扫描浏览历史或登录信息。配置失联暂停而非改用默认配置。
- 本地目录由清单声明版本；用内容摘要区分版本升高、同版本变化和固定目录被修改。同版本变化须显式重新部署；旧版由来源提供实际产物，不虚构本地版本历史。
- 远程来源只经 gh 获取 GitHub 元数据及产物；调用使用参数数组，不拼接用户输入到 shell。不读取或保存 Token，也不另写网络认证客户端。glab 是边界示例，不把 GitLab 适配加入本轮。
- Release 默认正式版，预发布版和降级由用户显式选择。显示来源标签与扩展版本的区别，安装版本以有效扩展清单为准；附件明确声明扩展版本时必须核对。存在歧义时展示候选并保存用户选择；附件变化后重新确认。
- 仓库子目录先解析到具体提交，再获取完整可加载产物；不执行仓库脚本。不存在完整产物时提示需要预构建内容。
- 获取到临时目录后验证 Manifest V3、名称、合法扩展版本、已声明的必要资源和可确定的摘要。版本采用 Chromium 扩展版本规则，不按通用语义版本猜测。
- 归档拒绝绝对路径、目录穿越、目标重名/大小写碰撞、符号链接逃逸等危险内容；限制解压资源用量。候选扩展根目录不唯一时让用户选择。本地复制也不跟随逃逸链接，不让来源与受管目录互相包含。
- 更新采用预检、临时产物、旧版备份、固定目录部署和保存记录。记录必要的操作阶段用于识别中断；不能确认恢复完成时显示恢复需要处理，不假装旧版可用。同一安装串行处理，避免两个操作相互覆盖。
- 浏览器 UI 手动路径作为初版基线。安装后显示待加载，更新后显示等待重载/验证；用户核对当前目标配置中的 ID 与版本后才记录用户确认。旧确认不得替新部署背书，历史确认须明确标为历史。
- 更新后明确加载失败（包括用户明确报告）恢复旧版文件，并再次等待浏览器重载/核对；状态不可读取保持待验证。文件恢复不能撤销扩展自身已执行的数据迁移，不做无损降级保证。
- 每个扩展独立执行批量更新，最初顺序执行即可；一个失败继续处理其他项。目标版本先展示，保留每项结果与阶段。
- 未验证的自动安装、自动重载和自动版本检查不作为本轮完成前提；不引入辅助扩展，不修改浏览器内部配置，不自动关闭或重启日常浏览器。

## Testing Decisions

已确认的主要测试入口是**界面调用的 Rust 安装用例**：从用户意图输入，检查返回状态、真实临时目录中的文件与重新打开后的安装记录。用真实文件系统验证安装、更新、备份和恢复；只在外部 CLI 边界使用可控响应，不围绕私有函数或 UI 内部结构编写镜像测试。

- 本地安装：有效产物可部署；来源不被改写；源目录随后移动不影响固定目录；重开应用能读到一致记录；未经核对保持待验证。
- 更新与恢复：有效升级和显式降级、同版本改动提示、固定目录改动冲突、失败前后旧文件、记录一致性与过期确认拒绝；注入获取、写入、替换失败及中断，确认结果可恢复且不虚报成功。
- 远程来源：CLI 缺失/未授权/失败，公开与私有响应，分页版本列表、歧义附件、仓库具体提交，摘要不符、危险 ZIP、清单或必要资源缺失。测试对外行为与文件结果，不固定内部调用顺序。
- 配置与偏好：不同配置安装互不影响；多个置顶与最后选择重开后保持；目标缺失不回退；旧文本标签须显式定位。
- 界面：在 macOS 做少量端到端冒烟检查，覆盖选择来源、后台进度、失败信息、手动加载指引与确认。核心行为不通过重复点 UI 验证。
- OpenCLI：在用户授权的 macOS Chrome 测试配置验证真实产物安装、连接检查、可用版本更新、管理器退出与浏览器重启后的持久性；下载/校验失败使用受控输入验证旧版保留。缺少适用真实更新版本时记录具体未覆盖项。
- 既有先例只有 throwaway GPUI 和 Chrome 持久安装实验，没有生产测试框架；复用其状态观测方法，不把实验代码直接并入生产代码。
- 按用户决定停止 Windows/Edge 专项验证，不新增这些验收门槛，不把原来的构建结果扩张为兼容性保证。

## Out of Scope

源码构建、已有扩展接管、自动浏览器注入、企业策略、账户或 Token 管理、GitLab 新适配、任意 ZIP URL、后台自动更新、版本锁定/通道订阅、跨配置迁移、多配置批量安装、Linux、签名与公证发布流程、等价产品 CLI，以及新版数据迁移的自动逆转。
