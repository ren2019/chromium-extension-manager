# MVP 最终审查修正

在已批准的 Rust 用例入口补充失败诊断验证：先复现检查失败重开后没有结果，再实现持久操作记录；混合来源批量测试先复现每项部署结果未保存，再接入独立结果。新测试还验证首次来源失败无需安装记录也能留痕、不同 Profile 的记录隔离，以及凭据样式文本不会进入文件。

操作记录保留最近 100 条，保存目标、可选安装 ID、时间、阶段、结果和受控诊断/下一步。它独立于安装记录和恢复事务，不以检查失败修改磁盘版本或生效确认；不保存原始 CLI 输出、路径、来源输入或凭据。历史页在重开后读取这些结果，也保留各安装当前操作状态。此记录用于必要诊断，不是无限审计日志。

单项与批量检查共同调用 `Manager::check_update`，避免 GUI 重复来源分派。GUI 的首次获取、校验及其他后台失败通过同一记录入口保存。

配置切换器约束名称按钮宽度并保留固定宽度的置顶按钮；忙碌时禁用所有已展开菜单操作，并关闭菜单。切换配置清空旧目标的预览、检查结果和弹窗；异步完成时再次核对目标。布局由根任务执行 macOS 冒烟确认。

验证：44 项核心测试、workspace clippy（所有 targets，warnings denied）、格式检查通过。未新增 Windows/Edge 验证。

## macOS 应用启动交接

后续实际浏览器验收改用正常 LaunchServices 启动 CEPM，排除了测试执行器退出时清理子进程的干扰。针对绑定在 `.app/Contents/MacOS` 中的浏览器，原生页面请求现经 `/usr/bin/open -n -a <确切应用> --args <绑定配置参数>` 交给系统启动；独立可执行文件保持原路径。没有使用默认 URL 处理器，没有修改浏览器配置、Keychain 或安全标志。

新增用例先复现请求仍直接启动浏览器二进制，再验证系统启动器、确切应用和 Profile 参数均正确；7 项 Profile 测试和 core clippy 通过。此变更不声称已解决浏览器保护偏好重置；真实持久性仍由根任务实测。
