2026-10-29。实现规格为 #2，界面依据已批准的 A 用户旅程。测试环境：macOS 26.6.2、Apple Silicon、Google Chrome 156.0.8078.74、OpenCLI CLI 1.8.6。

## 自动检查与制品

- Rust 安装用例使用真实临时文件和重开的记录；仅替换外部 `gh` 响应。
- 46 项核心测试覆盖本地安装、Profile、Release、仓库目录、安全更新/恢复、混合来源批量和持久诊断。

- `scripts/package-macos.sh debug` 产出原生 `.app`、架构标记 ZIP 及 SHA-256；CI 在检查后上传相同类型制品。
- 制品是未做 Developer ID 签名或公证的开发版。Windows/Edge 专项验证按用户决定不执行，不声明通过。

## 原生界面

使用独立应用数据目录和隔离的 Chrome Profile，实际操作 GPUI 窗口：

1. 从浏览器 version 页核对 Profile Path，绑定具体 Chrome 应用与配置。名称不是唯一身份。
2. 在左侧顶部切换配置；另一配置的列表为空，切回后恢复本配置的安装及待办数量。
3. 置顶两个配置，包括名称较长的配置；重开恢复最后选择，偏好保存到本地。
4. 本地文件夹选择、名称/版本预览、目标确认、文件部署、首次加载指引可完成。无效目录失败后仍可选择有效产物。
5. Release 获取在后台执行；真实分页版本列表可滚动选择旧版，附件与扩展根目录可明确选择。
6. 更新后显示磁盘安装版本和历史确认，未经本次核对不显示已生效。操作失败在历史页重开后仍可查看。

完整来源行为、降级、同版本重新部署、冲突及批量隔离由核心用例覆盖；没有重复用 UI 穷举同一逻辑。私有仓库通过 CLI 边界替身验证，没有为验收读取其他真实私有仓库。

## 浏览器交接与重启期间的异常

macOS 通过 LaunchServices 打开绑定的确切 `.app`，独立传递用户数据目录和 Profile 参数。Chrome 正确路由到该配置，但本版本会忽略命令行中的内部扩展页地址，显示新标签页。因此侧栏、详情和向导一直保留复制地址及粘贴说明；启动请求成功不代表页面打开或扩展生效。

早期测试中，执行器随 CEPM 退出清理了直接启动的 Chrome 子进程；后续改用正常应用启动方式隔离测试执行器生命周期。隔离配置曾出现 Chromium 受保护首选项重置，三个测试扩展的路径/清单元数据消失，保留开发者模式禁用标记。初始诱因缺少当次日志，尚不能确定。没有修改浏览器内部配置或 Keychain 来绕过它。

恢复通过正常浏览器 UI 加载仍完整的固定目录，再关闭/开启开发者模式清除残留禁用标记。之后沿最终 LaunchServices 路径正常退出并重启 Chrome，再退出 CEPM：OpenCLI 1.0.23、原 ID、启用状态和实时连接均保留；只读诊断确认首选项重置时间没有再次变化。该结果证明本次最终路径通过，不扩张为所有浏览器或所有异常退出情形的保证。
