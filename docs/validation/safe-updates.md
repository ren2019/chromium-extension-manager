# 本地安全更新与恢复验证

2026-10-29，规格 #2 / 任务 #4 的 Rust 核心实现。用户已批准的测试入口是界面调用的安装用例，使用真实临时目录和重开后的安装记录。GUI 接入及 macOS 冒烟由集成任务统一完成；本文不把它记为已验证，也不补做 Windows/Edge 验证。

## 行为

- `check_local` 从已记录的本地来源预览；`prepare_update` 接收已验证的 `Preview`，供其他来源复用。预览冻结内容，按 Chromium 数字段规则比较版本，区分升级、降级、同版本重新部署和无变化。
- `apply_update` 必须收到与预览一致的明确选择。固定目录与扩展 ID 不变；SHA-256 内容基线发现手动修改就暂停。更新清空本次生效版本，旧确认放入历史，新的部署代数使过期核对失效。
- 每个安装保留一份尚待核对的旧版。下一次部署前先确认或报告加载失败，避免覆盖仍需恢复的备份。`report_load_failure` 恢复文件后仍需重新核对；不承诺撤销扩展数据迁移。
- 持久日志记录准备、已部署和恢复中状态。`apply_update_with_progress` 暴露实际阶段供界面显示。应用重开会尝试恢复未完成替换；无法确认恢复完成的安装显示 `recovery_required` 和原因，不影响其他安装。
- 旧版记录若没有可信内容基线，不根据当前目录静默建立基线；提示保留旧目录并重新安装。

## 验证结果

`cargo test -p cepm-core --locked`：17 项集成测试通过（原有 7 项 + 更新 10 项）。`cargo clippy -p cepm-core --all-targets --locked -- -D warnings` 与格式检查通过。

逐步观察到失败再实现的行为包括：升级及新核对、手动修改冲突、显式同版本部署/降级、加载失败恢复、阶段中断恢复、替换失败隔离、目录链接冲突、字面反斜线文件名的摘要区分，以及备份损坏时保留当前文件。

- 中断通过真实操作进度回调在准备日志、旧文件已备份、新文件已部署、安装记录已保存四个边界抛出 panic，随后释放实例并重新打开；断言旧文件、旧版本记录、待核对与过期确认拒绝。未伪造恢复成功，不模拟操作系统断电持久性。
- 写入失败使用只读记录目录；替换失败使用只读安装父目录。恢复尚不能落盘时标记待处理，修复权限并重开后恢复。另一个安装仍可确认。
- 已完成更新重开仍保持新文件与待核对，明确加载失败才恢复。备份内容损坏时不移走当前文件，重开仍提示待处理。
- 同版本重新部署后，即使浏览器版本文本相同，旧部署代数也不能确认新部署。降级走相同备份与核对流程。

测试没有修改浏览器数据或运行来源脚本。尚未在本票中验证 GUI 和 OpenCLI；这些由集成验收记录覆盖。
