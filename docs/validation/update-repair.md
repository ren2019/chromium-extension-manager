# 更新失败与原备份保留（#13）

2026-10-30。按 #10 最新批准行为，用户反馈失败只记录失败、保留当前文件与历史生效版本；恢复旧文件是独立的明确选择。PRD 中旧的自动回滚措辞已同步。部署事务本身失败仍尝试恢复，不牺牲旧文件保护。

## 实现与验证

- 更新提醒使用一次结果选择：确认更新完成 / 更新失败。关闭不提交，返回详情后失败主操作是重新安装，仍可选择其他版本、重新核对或显式恢复。
- 同版本重装重新获取保存的本地版本、Release 标签+确切附件+根目录，或仓库固定提交+子目录；不改装最新版本。仓库重装保留原跟踪引用供后续检查。
- 首次更新的 `old` 备份与后续修复的临时回退文件分别保存。已待核对的部署可再次修复或明确换版本，而不先假确认、不删除原恢复备份。每次部署推进代数。
- 旧日志可读取；修复子阶段记录仅添加可选字段。重新打开处理修复中断后仍保留原备份，明确恢复实际返回原版文件。
- 单次与批量检查结果进入同一界面结果缓存；显示目标版本、无新版本或检查失败。文件替换后清除对应旧结果；检查时间使用已有操作记录，不改安装/更新时间。
- 首次加载说明同时按原生试用反馈收紧：紧凑按钮行、管理页轻量入口、移除 ID 机制说明和重复底部关闭按钮。加载/更新提醒仅覆盖内容区，侧栏可继续使用。

公开 `Manager` 用例的红绿测试覆盖：反馈失败不回滚、两次相同版本重装后仍可恢复原文件、Release 最新版本变化不影响确切旧产物重装、仓库按保存提交重装。额外回归验证所有五个持久阶段中断、重开后重试/恢复、本地确切版本不可获取、文件冲突，以及既有批量独立结果。
